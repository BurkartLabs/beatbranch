# BRIEF — beatbranch

Size: L (preview M)
Stage: Brief
Scorecard: the RUBRIC gate table in [docs/DESIGN.md](docs/DESIGN.md)

## One sentence

A place where a producer registers, creates a project (public or private), uploads the DAW project file — FL Studio, Ableton, Logic, Reaper, Studio One, Bitwig — and from then on works the way developers do: branches, commits with a message, diffs that show what changed, merges when the other branch was better, invites and forks; and where the site can actually **see inside** the project — tracks, patterns, tempo, plugins, samples — and play the stems in the browser.

## What we will measure first

The single number that keeps or kills this: **Commits per active project per week.** After the brother and ten invited producers have used it for four weeks: below 1 commit per active project per week, it is a file drop with extra steps; above 3, the version model is part of how they work. Second number: **share of projects with more than one branch**, which is whether the Git-like part is used at all (target > 25%).
